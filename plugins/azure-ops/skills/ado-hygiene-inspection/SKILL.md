# Періодична інспекція гігієни

Read-only: за замовчуванням жодного запису — лише звіт у чат. Публікація на вікі чи заведення елементів за результатами — тільки після явного «так» користувача.

**Що інспектуємо.** Лише проєкти поточного користувача. Обліковку бери з сервера (`core_get_identity_ids`, або `wit_work_item` дією `my`), не з тексту розмови: у наступного користувача вона буде інша. `core_list_projects` повертає і чужі проєкти — інспекція їх не читає й у звіт не бере, навіть коли доступ є. Проєкт для перевірки називає користувач або CLAUDE.md робочої теки; «перевір усе» звужуй до своїх проєктів і скажи про це у звіті.

## Джерело порогів

Пороги, словник тегів, regex гілок, формат підсумків — таблиці на вікі-сторінці «Конвенції» проєкту. Власних порогів НЕ вигадуй. Сторінки немає — дефолти (елемент без змін 14 дн, активний PR 7 дн, гілка без комітів 30 дн, документація 180 дн) із позначкою «дефолт, конвенцій не знайдено».

Сторінка є, але порога для конкретної перевірки в ній немає — те саме: дефолт із позначкою, і окремим рядком у звіті запропонуй внести поріг у конвенції або прибрати перевірку. Мовчазний дефолт робить тижні непорівнянними так само, як вигаданий.

## Перевірки

Робочі елементи (wit_query; стани Agile-процесу: New/Active/Resolved/Closed/Removed):
1. Відкриті без змін довше порога.
2. Active без виконавця.
3. Відкриті без ітерації (IterationPath = корінь проєкту).
4. Хвости завершених спринтів: ітерації з датами через work → відкриті елементи в минулих спринтах.
5. Баги в New довше порога тріажу.
6. Закриті за період: останній коментар не у форматі підсумку з конвенцій. Додатково для **Task і Bug** — порожній Completed Work. Історії та Feature на години не перевіряй, якщо конвенції не кажуть протилежного: час обліковується на задачах, і порожнє поле в батька — норма, а не порушення.
7. Теги поза словником конвенцій.

Репозиторії (repo_*):
8. Гілки поза regex конвенцій; злиті або мертві гілки, крім постійних.
9. Активні PR старші порога; PR без звʼязаного робочого елемента.
10. Свіжість комітів: repo_search_commits вимагає searchText, а repository передається масивом; вікі-репозиторій пошуком НЕ індексується.

Документація (wiki):
11. Сторінки в чинному статусі, де поле «Оновлено» старше порога документації (саме за полем на сторінці, не за комітами — див. п. 10).

## Звіт

Розділи «Робочі елементи / PR та гілки / Документація»; кожне порушення: ID — назва — вік — URL. Наприкінці «Топ-3 дії на тиждень». Великий список — топ-20 найстаріших плюс загальний лічильник.

## Червоні прапорці

- «Розумний поріг я й сам знаю» → поріг береться з конвенцій, інакше тижні не порівнянні між собою.
- «Заодно й виправлю» → інспекція не мутує. Виправлення — окремі задачі після звіту.
- «Пайплайни теж перевірю» → скоуп перевірок фіксований конвенціями; розширення — пропозицією у звіті, не самодіяльністю.
