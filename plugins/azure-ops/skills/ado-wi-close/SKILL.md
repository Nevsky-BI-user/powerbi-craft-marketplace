# Закриття елемента: «закрив — залогуй»

Закриття без годин і підсумку — втрачений слід. Стан, час і результат змінюються одним ритуалом, а не трьома окремими проханнями до користувача.

**Чиє це.** Закриваємо елементи лише в проєктах поточного користувача, а години логуємо на його обліковку, взяту з сервера (`core_get_identity_ids`, або `wit_work_item` дією `my`), не з тексту розмови. Елемент належить іншій людині — не чіпаємо, кажемо про це користувачу.

## Порядок

1. **Перевір ціль** (wit_work_item): тип, стан, Title, звʼязки. Заголовок не вʼяжеться з розмовою — покажи його користувачу й перепитай: імовірно, переплутаний номер.
2. **Хвости.** Відкриті дочірні Task або активні PR у звʼязках — попередь і спитай, чи закривати попри них.
3. **Час.** Візьми фактичні години з розмови або спитай; облік кратний 0.5 год. Онови Completed Work. Remaining Work — ПРИБЕРИ значення (порожнє поле), не пиши 0: правила процесу на закритому елементі вимагають порожнє, інакше помилка виду TF401320 InvalidNotEmpty.
4. **Підсумок** (wit_work_item_comment_write) — формат із вікі-сторінки «Конвенції» проєкту; дефолт:
   ```
   Закрито: <що зроблено, один-два рядки>
   Результат: <посилання — PR, сторінка вікі, артефакт>
   ```
5. **Стан** → термінальний для типу (Agile: Closed); прямий перехід заборонено — йди через дозволений проміжний. Стан міняй ПІСЛЯ годин і коментаря: частина полів закритого елемента стає read-only.
6. **Верифікація:** перечитай стан і Completed Work; віддай користувачу назву, новий стан, години, посилання.

Елемент уже закритий — нічого не пиши, просто скажи про це.

## Червоні прапорці

- «Користувач просив лише закрити» → у проєкті з конвенціями «закрити» включає години й підсумок. Не знаєш годин — спитай; це не зайве питання, а частина запиту.
- «Remaining Work = 0» → ні. Поле має бути порожнім.
- «Коментар допишу потім» → «потім» не настає. Підсумок — до зміни стану.
- «Стан спершу, деталі потім» → закритий елемент може не прийняти правки полів.
