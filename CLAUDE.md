# powerbi-craft-marketplace — правила проєкту

Публічний маркетплейс скілів Claude Code (MIT) + сайт-каталог на GitHub Pages:
[nevsky-bi-user.github.io/powerbi-craft-marketplace](https://nevsky-bi-user.github.io/powerbi-craft-marketplace/).
Репо містить власні плагіни зі скілами, а сайт додатково описує чуже оточення
автора — набори Anthropic, Microsoft, Kurt Buhler і окремі скіли з публічних
джерел.

## Карта репозиторію

```
.claude-plugin/marketplace.json   перелік плагінів і версій (джерело правди)
plugins/<плагін>/                 .claude-plugin/plugin.json + skills/<скіл>/SKILL.md
scripts/build_catalog.py          plugins/ + CHANGELOG.md → site/src/catalog.json (запускає CI)
scripts/build_inventory.py        ~/.claude/skills цієї машини → site/src/inventory.json (лише локально)
scripts/skill_sources.json        реєстр джерел, який дописує add_skill.py (накладається на build_inventory)
scripts/add_skill.py              ставить зовнішній скіл і реєструє його джерело
scripts/sync_from_local.py        публікує власні скіли з ~/.claude/skills у plugins/
scripts/uk_descriptions.json      українські підказки скілів для сайту
scripts/validate_repo.py          перевірка репо (той самий скрипт, що й у CI)
CONTRIBUTING.md                   правила для зовнішніх PR: інваріанти CI, санітизація, ліцензія
.claude/commands/add-skill.md     /add-skill — ритуал «Додати скіл, який кинув користувач» як команда
.claude/commands/release.md       /release — «Оновити власний скіл» + версії в обох маніфестах, CHANGELOG, uk_descriptions.json, README, валідатор
site/src/                         React+Vite сайт; components/InstallAll.tsx — блок «Встановити все»
```

## Додати скіл, який кинув користувач

Користувач кидає посилання в будь-якій формі (`owner/repo@skill`,
`owner/repo/skills/name`, URL на теку в GitHub) — далі все роблю сам, нічого
не перепитуючи:

```bash
python scripts/add_skill.py <те, що кинув користувач>
```

Скрипт знаходить теку скіла в репозиторії, викачує **всі** її файли в
`~/.claude/skills/<скіл>/`, визначає, чи репо є маркетплейсом, реєструє джерело
в `scripts/skill_sources.json` і перебудовує `site/src/inventory.json`. Форма
`owner/repo` без назви скіла показує список доступних скілів і нічого не ставить.

Далі — те, чого скрипт не робить, бо це проза й перевірка:

1. **Український опис скіла** в `scripts/uk_descriptions.json` (без нього на
   картці буде англійський опис автора). Одне речення: що робить, коли корисний.
2. **Примітка джерела** в `scripts/skill_sources.json`, якщо джерело нове —
   скрипт кладе туди англійський опис репо з GitHub. Переписати українською;
   якщо репо є маркетплейсом, але його плагін тягне десятки зайвих скілів,
   сказати це прямо і лишити `marketplace: false`, щоб на картці був промпт на
   один скіл, а не команда, що ставить усе.
3. `python scripts/build_inventory.py` ще раз (описи потрапляють у знімок).
4. `npm --prefix site run build` — має пройти без помилок tsc.
5. Коміт (`site:` у першому рядку) зі `scripts/*` і `site/src/inventory.json`,
   пуш, дочекатись обох перевірок CI, перевірити живий бандл на наявність
   нової назви (сторінка кешується — тягнути з `?v=<timestamp>`).

MCP-сервери, які часом ідуть у парі зі скілом, **не** налаштовую сам: це зміна
конфігурації користувача. Кажу, що саме поставити, і лишаю рішення йому.

## Оновити власний скіл у маркетплейсі

Джерело правди для власних скілів — `~/.claude/skills`: вони правляться під час
роботи, а репозиторій є знімком для інших. Тому напрямок публікації один:

```bash
python scripts/sync_from_local.py             # хто розійшовся з майстер-копією
python scripts/sync_from_local.py --apply-all # перенести все, що розійшлось
```

Скрипт дорогою знеособлює локальні шляхи (`C:\github\<проєкт>` → плейсхолдер),
а якщо після цього конкретика лишилась — зупиняється й називає файл, не
доводячи справу до CI. Скіли з навмисною різницею (`icon-set-manager` тримає
локально справжні шляхи, `pbi-corporate-theme` — логотипи) перелічені в самому
скрипті й ніколи не переносяться.

**Зворотний напрямок — тільки руками й прицільно.** Якщо новішим виявився репо
(наприклад, там уже знеособлений приклад, а локально ще стара назва), правити
треба локальну копію: `--apply-all` у зворотний бік поверне в публічне саме те,
що звідти прибирали.

Після перенесення: підняти версію плагіна в **обох** маніфестах, дописати
CHANGELOG (тире довге), перевірити `python scripts/validate_repo.py`.

## Що не потрапляє в це репо ніколи

- **Бренд-активи.** Логотипи компанії живуть тільки локально; скіл
  `pbi-corporate-theme` спеціально постачається без них. Скрипт публікації
  скілів має відсіювати теку `logos`.
- **Проєктна конкретика.** Назви бойових звітів, внутрішні коди задач,
  посилання на документи, яких немає в постачанні. Заміри лишаються, але
  знеособлені («a production report»). Шукати залишки **завжди**
  регістронезалежно: `git grep -i`.
- **Локальні шляхи й імʼя користувача.** Це перевіряє і `validate_repo.py`
  (по `plugins/**`), і санітизація в `build_inventory.py` (по знімку).
- **Скіли приватних проєктів** (`rayfin-bootstrap`, `kpi-data-entry-app`) — на
  сайт не публікуються.
- **CHANGELOG не цитує те, що прибирає.** Запис про чистку, який називає
  видалені імена, повертає їх у бандл сайту.

## Інваріанти, які ловить CI

`validate_repo.py` (workflow `validate`, Ubuntu + Windows):

- `name` у фронтматтері == назва теки скіла;
- версія в `plugins/<p>/.claude-plugin/plugin.json` == версія в
  `.claude-plugin/marketplace.json` (**піднімати обидві разом**);
- кожен плагін на диску заявлений у маніфесті, і навпаки;
- жодних `C:\Users\HEAVY…`, `HEAVY_METAL`, `C:\github\…` у `plugins/**`;
- LF у `*.sh` (CRLF ламає хук на Windows-checkout).

`build_catalog.py` (workflow `pages`) читає CHANGELOG регуляркою
`^##\s+([\d.]+)\s+—\s+(\S+)` — **тире має бути довге** (`—`), інакше запис
мовчки не потрапляє на сайт.

## Два різні JSON сайту

- `site/src/catalog.json` — **похідний**, його щоразу перегенеровує CI із
  `plugins/` і CHANGELOG. Руками не правити.
- `site/src/inventory.json` — **знімок оточення цієї машини**. CI її не бачить,
  тому файл будується локально й комітиться з датою знімка. Оновлювати після
  кожної зміни в `~/.claude/skills`.

## Git

Коміти прямо в `main` (репо однокористувацьке), перший рядок англійською в
наказовому способі, тіло — деталями українською. Префікс `site:` для змін, що
стосуються лише сайту; для них запис у CHANGELOG не потрібен — він про версії
плагінів і скілів. Багаторядкові повідомлення передавати через
`git commit -F <файл>`, бо PowerShell псує кирилицю в інлайн-рядках.
