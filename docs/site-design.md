# Сайт-каталог (site/) — дизайн-нотатка

Затверджено 2026-08-18: каталог статичний з git, Supabase — лише лічильники;
опис скіла — клік-розгортання картки (варіант Б); сайт живе в site/ цього репо.

## Потік даних

```
plugins/**/SKILL.md + plugin.json + CHANGELOG.md
        │  (пуш у main)
        ▼
scripts/build_catalog.py  →  site/src/catalog.json   (CI, крок перед збіркою)
        ▼
vite build  →  site/dist  →  GitHub Pages
```

- Джерело істини — фронтматтери скілів. catalog.json — похідний артефакт;
  закомічена копія потрібна лише для локального dev, CI її перегенеровує.
- Додавання скіла в plugins/ оновлює сайт без жодного ручного кроку.
- Битий фронтматтер валить validate-воркфлоу і build_catalog (обидва парсять YAML).

## Supabase (опційний шар)

- `supabase/migration.sql`: таблиця copy_events (insert-only для anon, RLS),
  агрегат-вʼю copy_counts (security_invoker=off свідомо — віддає лише суми).
- Ключі приходять у збірку як repo variables `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_ANON_KEY`. Anon key у публічному бандлі — нормально за таких
  політик; максимум зловживання — накрутка лічильника.
- Без ключів telemetryOn=false: сайт повний, лише без бейджів «топ».
- Події: marketplace / plugin / skill-view / skill-prompt / all-terminal / all-prompt.

## UX-рішення

- Чіп скіла → картка під рядком: короткий опис, тригери, install плагіна,
  «лише цей скіл» — промпт для Claude Code (CLI ставить лише плагіни цілком).
- Глибокі посилання: #<skill-name> відкриває картку і скролить до неї.
- «Встановити все»: таби термінал / промпт для агента.
- «Як почати» містить вмикання автооновлення (для сторонніх маркетплейсів
  воно вимкнене за замовчуванням) і disclosure про хук та субагентів.
- Темна тема — prefers-color-scheme, палітра з того ж фіолетового бренду чіпів.

## Інвентар середовища (розділи-групи, з 2026-08-18)

- Сайт — ЄДИНИЙ каталог середовища: powerbi-craft + групи Anthropic / Microsoft /
  Kurt Buhler / окремі скіли, кожна — власний розділ верхнього рівня зі своїм
  кольором; шапка нейтральна («Каталог скілів Claude Code»), без метрик і фокуса
  на powerbi-craft — групи рівноцінні (рішення 2026-08-18). Липка міні-навігація
  згори скролить до розділу і показує живі лічильники (при пошуку — знайдені
  унікальні). Пошук — у липкій панелі, клавіша «/», кнопка «↑ Нагору».
- Концепт C (обраний користувачем із макетів A–D): на екранах ≥1100px ліва
  закріплена панель контексту активної групи — іконка, опис, лічильник,
  команда підключення, зміст підблоків (клікабельні якорі `p-<plugin>` /
  `src-<source>`); на вужчих — компактний липкий рядок групи під навігацією.
  Активний розділ рахується від прокрутки (scroll-listener, НЕ
  IntersectionObserver — той глухий у вбудованих переглядачах), goTo — ручний
  scrollTo з урахуванням scroll-margin.
- Іконки: PLUGIN_ICONS (емодзі) на картках плагінів powerbi-craft і в
  SECTION_INFO для груп. Картки плагінів — CSS-grid, вирівняні по висоті,
  без англійських абзаців; команди встановлення переносяться (без скролбара).
- Українські описи скілів: кураторський словник scripts/uk_descriptions.json
  (182 скіли, згенеровано воркфлоу переклад→верифікація→виправлення
  2026-08-18); обидва білдери підмішують shortUk, фронт показує його в
  CSS-підказці при наведенні на чіп і в картці скіла; пошук шукає і по uk.
  Нові скіли без запису в словнику чесно падають на англійський short
  (білдер каталогу друкує список без-uk при збірці).
- `scripts/build_inventory.py` запускається ЛОКАЛЬНО на машині автора (CI її не
  бачить) і генерує `site/src/inventory.json` — знімок скілів ПК з датою:
  кеш маркетплейсів (`~/.claude/plugins/cache`) і окремі `~/.claude/skills`
  поза powerbi-craft. Проєктні скіли приватних репо на сайт не потрапляють
  (рішення 2026-08-18).
- Окремі скіли згруповані за ПЕРЕВІРЕНИМ публічним джерелом (SOURCE_META /
  SKILL_SOURCE у білдері; перевірка — лістинг GitHub API або пряме посилання
  в SKILL.md, 2026-08-18). Джерело-маркетплейс → команда
  `claude plugin marketplace add`; репо без маркетплейсу, але з текою скіла →
  промпт sparse-checkout на картці; без канонічного джерела (emil-design-eng,
  humanizer + авторські graphify, model-orchestration) — чесна позначка
  «локальний».
- Для наборів Microsoft показуються і сирі, і унікальні кількості (мета-плагіни
  перекриваються навмисно); у шапці сайту — загальні цифри середовища
  (скілів / плагінів / джерел), пораховані з catalog.json + inventory.json.
- Оновлення знімка — перезапустити скрипт і закомітити JSON. Скрипт сам валить
  збірку, якщо у вихід просочився локальний шлях чи імʼя користувача.
- Вбудовані скіли застосунку Claude (docx/pptx/xlsx…) у знімок не входять —
  вони частина застосунку, а не встановлення.

## Підключення Supabase (одноразово)

1. Створити проєкт на supabase.com (безкоштовний тір достатній).
2. SQL Editor → виконати supabase/migration.sql.
3. Repo → Settings → Secrets and variables → Actions → Variables:
   `VITE_SUPABASE_URL` = https://<ref>.supabase.co,
   `VITE_SUPABASE_ANON_KEY` = anon public key (Settings → API).
4. Перезапустити воркфлоу pages (або будь-який пуш у main).

## Розкладка розділу: смуга замість бічної панелі (2026-08-19)

Бічна панель контексту (концепт C) прожила один день і поступилась концепту D:
липка смуга розділу всередині `.topnav`. Причина — панель ліворуч віддавала
280px постійно, а користь давала лише зверху екрана; на вимогу «вибір не дає
жодної користі» перелік плагінів мав стати робочим, а не декоративним.

Що діє тепер:

- `.sectionband` живе всередині липкої навігації, тож не потребує власного
  `top` і не воює з нею за стек. Показує іконку, назву групи, лічильники,
  посилання на репо, кнопку копіювання команди та перелік плагінів чіпами.
- Опис групи в смузі показується лише там, де переліку плагінів немає
  (Встановити все / Вимоги / Як почати). У групах корисніший список.
- Клік по чіпу плагіна гортає до картки **і** підсвічує її (`.flash`,
  1.9s, з `prefers-reduced-motion`-запобіжником) — інакше клік читається як
  промах.
- Кожна картка плагіна має свій опис англійською (мова авторів); українською
  лишаються описи скілів у підказках.
- Висота навігації міряється в рантаймі (`ResizeObserver` → `--navh`), від неї
  рахуються `scroll-margin-top` якорів і поріг активного розділу. Хардкод
  висоти ламався щоразу, коли рядок чіпів перегортався.
- Бюджет висоти: липка шапка тримається ~154px на 1280×720 (21% екрана),
  ~236px на телефоні. Що допомогло: команда підключення стала кнопкою замість
  повного рядка, чіпи powerbi-craft без префікса `pbi-`, пошук в один рядок з
  навігацією.
- Мобільний рядок групи (`.groupstrip`) прибрано: смуга працює на всіх
  ширинах, на вузьких ховає опис і кнопку, а чіпи гортаються горизонтально.

Граблі: у схованій Browser-панелі Claude заморожені і `ResizeObserver`, і
події скролу, тож `--navh` лишається від попереднього розміру, а активний
розділ не перемикається. Перевіряти після `navigate` з примусовим
перезавантаженням і кликати `window.dispatchEvent(new Event('scroll'))` вручну.

## Розділ «Що потрібно системі»

Три картки (працює всюди / потрібен python 3 / потребує Windows) плюс чесна
нота про межу перевіреного: наживо ганялось лише на Windows 11. Текст
оновлювати разом зі зміною залежностей — це єдине місце, де користувач бачить,
що саме в нього не спрацює.

## Один блок = одна команда (2026-08-19)

Правило: скільки команд терміналу, стільки й блоків. Наслідки для верстки:

- `coverPlugins()` бере мінімальний набір плагінів, що покриває всі скіли групи
  (жадібне покриття). Там, де плагіни не перетинаються (powerbi-craft,
  Anthropic, Kurt Buhler), повертає їх усі без змін — кожен і так має свою
  команду. Microsoft пакує 46 скілів у 6 плагінів, де 42 повторюються до пʼяти
  разів; лишається 2 картки (`skills-for-fabric` 42 + `powerbi-authoring` 4).
  За однакового покриття виграє плагін, названий як репозиторій.
- Решта нарізок їде в `<details>` «Ті самі скіли іншими нарізками» з чесним
  поясненням, що це підмножини вже показаного.
- `clusterSkills()` ділить довгий список усередині блоку по підкатегоріях із
  самих імен скілів (`*-authoring-cli` → Авторинг, `*-consumption-cli` →
  Споживання, `*-operations-cli` → Операції, `*-migration` → Міграції,
  `powerbi-*` → Power BI, решта → Решта). Кластери менші за 3 скіли зливаються;
  при <10 скілах або <2 осмислених категоріях список лишається плоским.
- Команда встановлення НЕ повторюється в розгорнутій картці скіла. Раніше
  кожен скіл показував ту саму команду плагіна ще раз. Лишились тільки справді
  інші команди: промпт «лише цей скіл» у powerbi-craft і sparse-checkout для
  джерел без маркетплейсу.
- Перелік у смузі розділу будується з того самого `coverPlugins()`, інакше
  чіпи вели б на якорі карток, яких на сторінці більше немає.

## Ширина карток: від 10 скілів — на весь рядок

Сітка `grid-template-columns: repeat(auto-fill, …)` лишала порожню колонку
щоразу, коли карток у рядку менше, ніж треків: два блоки Microsoft на три
колонки означали третину екрана порожнечі. Замінено на гнучкі рядки
(`display: flex; flex-wrap: wrap`), де картка має `flex: 1 1 min(400px, 100%)`
і сама розтягується на вільне місце.

Правило ширини (`WIDE_FROM = 10` в `InventorySection.tsx`, спільна константа
для всіх трьох місць із картками): плагін чи джерело з десятьма і більше
скілами отримує клас `wide` і займає рядок цілком, бо довгий список чіпів у
піврядку розповзається на десяток рядів. Менші картки стоять по кілька в ряд.

`align-items: flex-start`, а не `stretch`: інакше коротка картка поруч із
довгою роздувалась до її висоти і сама перетворювалась на порожній прямокутник.
